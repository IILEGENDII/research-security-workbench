Source and integrity lack a producer timestamp and intrinsically bound subject. Import observation times and claimed subjects come from the operator. Backup and restore are import-only. The published backup examples and parser campaign reports are evidence from upstream synthetic runs. A fixture import does not record a local execution.

The packaged source and integrity examples are stdout from isolated invocations of the pinned modules. The source sample containing a risky call was parsed only. The integrity sequence used an ephemeral signing key in memory, a same-length file edit and a different public key. Dependency examples are stdout from the real offline audit command over generated inventory and clearly labeled synthetic advisory responses. The backup and ordinary restore examples are the published Project 3 sample JSON blobs. The grid example is Project 4’s published grid campaign blob. See the upstream notices in the packaged fixtures directory. These are development tests and synthetic upstream reports.

The integration suite regenerates the source, integrity and advisory outputs and reimports the published samples from exact Git objects. Separately, it executes all three collection paths, a new 64-attempt bundled campaign, a real full read of a new disposable restic repository and a recovery plan that must leave the destination empty. The fixture demo has one deliberately constructed synthetic independent-digest recovery control. It performs no recovery operation.

Raw source and integrity reports have no producer timestamp. Recovery reports expose snapshot time (for audits) and the pinned snapshot ID (for recovery). Campaign reports identify their tool/target/protocol and per-case evidence, but give no producer observation time. Dependency reports carry the advisory check timestamp and inventory digest. These timestamps have different meanings. They cannot substitute for one another.
