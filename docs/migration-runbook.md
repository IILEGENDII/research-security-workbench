# Migration and recovery runbook

1. Establish who owns each asset and which transfers are permitted. Obtain applicable research or institutional approvals before any transfer. Use synthetic data for the rehearsal.
2. On the private workstation, apply supported OS updates, limit administrative accounts, enable disk encryption and verify recovery-key custody. Protect the verification public key and the policy separately from the dataset and writable receipts. Keep private signing keys offline.
3. Create the signed source inventory through a trusted baseline process. Record its revision, date and subject. Keep an independent offline or immutable backup with a documented recovery procedure. Confirm storage capacity and the scope of the repository check. Use established encrypted transfer tools and approved channels.
4. On arrival, verify the trusted public key, signed baseline and copied files. Review additions, missing files, same-size modifications and unreadable entries. Compare the package inventory with the approved versions. Record what native components fall outside PyPI coverage. Review findings before running transferred code.
5. Run the scoped workbench collectors and import separately obtained backup evidence. Review the read scope, snapshot ID and age. Arrange an explicitly approved isolated restore outside the workbench. Use independently trusted expected digests to establish source equivalence before retiring the source. Keep the original copy until recovery and arrival verification meet the operator's requirements.
6. Retain the exact policy, reports, receipts and assessments in separately protected storage. Repeat time-sensitive checks after software updates, baseline changes and on the agreed schedule. Record the human decision and remaining exceptions privately.

The workbench reports evidence for these decisions. Encryption, backup custody, correct key enrollment, transfer permissions and restore execution remain operator responsibilities.
